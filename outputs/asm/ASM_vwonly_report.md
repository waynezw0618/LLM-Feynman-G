# vw-only（b23）重训练实验报告

**日期**: 2026-10-11
**数据**: Yang & Wang 2018 (JFM 838) 旋转槽道流 DNS，Re_τ=180，Ro_τ={7.5, 15, 30, 75, 150}
**任务**: 只拟合雷诺应力 `<vw>` 分量（b23 = <vw>/(2k)），loss 仅含 b23 相关项

---

## 1. 背景与动机

用户实际应用（涡量输运方程 (2)）只用到雷诺应力的 **<vw>** 分量（其二阶横向导数项）。
此前所有单公式模型（mix_lgf_go、mix_pysr）用 **6 分量联合 loss** 训练，b23 因幅值
尺度悬殊（b23 RMS 仅 b11 的 ~1/10）在全局 loss 中几乎无权重，导致 b23 单独 NMSE
高达 2.2–6.1（比零预测还差）。

**假设**：把问题退化为单输出符号回归（目标仅 b23(y)），可以在不引入新骨架的情况
下大幅改善 b23 精度。

**结论（先行）**：假设成立，且改善幅度远超预期——最优组合 loss_vw = **0.110**，
比旧 mix 单公式（同口径重算 3.70）好 **34×**。

## 2. 实验设计

### 2.1 覆盖矩阵

| 维度 | 取值 | 说明 |
|---|---|---|
| variant | v / g / e / m | v=W̄, g=W̄+Ω, e=W̄+2Ω（17 特征）；m = 三变体混合（43 特征） |
| method | pysr | PySR（60 迭代，maxsize=30，加权 1/(Nv·var)） |
| | lgf_go | LGF + ginit_only（LLM 仅出初始种群，进化离线） |
| | lgf_mg | LGF + 完整 M_GUIDE |
| backend | heuristic | ⚠️ 本轮 `LGF_LLM_API_KEY` 未设置，LGF 均为离线假 LLM |

### 2.2 数据与统一评估口径

- 训练目标：b23 = <vw>/(2k)，5 工况 × 127 点，联合拟合，仅允许全局常数 C#（禁逐工况 K#）
- **NMSE 口径**（本报告全部数字统一）：逐工况 `mse / var_vw(该工况)`，loss_vw = 5 工况均值
- **基线重算**：旧 mix_lgf_go / mix_pysr 的 `preds_best.npz` 取 vw 行，按上述同一口径重算
  （旧报告 per_comp 数字与此一致，可直接横比）
- 验收护栏：max|θ| 无爆参（最大 17.5）、frac_oor=0（无值域越界）、无逐工况常数

### 3.2 关键读数

1. **全部 10 个完成组合（0.11–0.44）都显著优于两条基线（3.7 / 5.9）**——改善 8–34×。
   旧模型 b23 之所以差，首要机制确实是"弱分量在 6 分量全局 loss 中无权重"（10-10 定论），
   换成 b23-only loss 后无需新骨架即根治。
2. **最优 lgf_mg/g = 0.110**，且 5 工况全部 ≤0.30，是唯一在所有 Ro 上都进入 0.1 量级的模型。
3. **PySR 在单输出任务上极快（~20 s）且竞争力强**（e/m 变体 0.15），复杂度 15–30。
4. **高 Ro（150）仍是最难工况**：除 pysr/e（0.200）外，各组 worst 都出现在 Ro150。
5. m 变体（43 维混合特征）PySR 正常完成且公式最简（复杂度 15）；但 **LGF 在 43 维特征上
   单代评估过慢**（heuristic paramfit 单 start 无迭代上限，budget 只在 start 之间检查），
   80 分钟未出第一代结果，已终止。历史 mix 跑批（同 43 维、3810 行）耗时 43 分钟可完成，
   本次慢的原因是个体公式结构落入 exp/log 病态区 + budget=600 切分更细。

## 4. 最优模型详情

### 4.1 lgf_mg/g（全局最优，loss_vw = 0.110）

```
b23 ≈ C4·roloc / ((C1 + C2·s2o2)·(C3 + roloc))

(C1, C2, C3, C4) = (−3.3466, 8.550e−4, 7.0629, −0.2180)
```

- 数值验证：手写公式 vs preds_best.npz 逐点最大误差 = 0（精确一致）
- 结构解读：`roloc/(C3+roloc)` 为 **局部旋转数的饱和函数**（低 Ro 线性增长、高 Ro 饱和），
  `1/(C1+C2·s2o2)` 为应变-旋转交叉不变量的弱调制，符号由 C4<0 与 C1<0 共同保证为正
- 护栏：max|pred|=0.057（真值峰 0.0375，有轻微过冲）、frac_oor=0、无逐工况参数 ✅
- 注意：raw DSL 中冗余参数 C5·(C4·1) 被编译器折叠，等效 4 参数形式如上

### 4.2 pysr/m（最简公式，loss_vw = 0.152，复杂度仅 15）

```
b23 ≈ 0.04994 · exp(−2.8393/roloc) · exp(1.0895·(s2o2_e − T10_v)/ret)
```

- 结构解读：`exp(−2.839/roloc)` 为 **roloc 倒数的衰减**（与 lgf_mg/g 的饱和型互补），
  指数项混合 e-变体不变量 s2o2_e 与 v-变体张量基 T10_v——算法在 43 维混合特征里
  跨变体取材，与 mix 框架设计意图一致

### 4.3 pysr/e（工况最均衡，worst 仅 0.246）

```
b23 ≈ 0.03774·((√so2 + exp(s2o2/ret))·exp(eta2²/s2o2) + 0.1739)·exp(4.017·eta2/s2o2)
```

- 5 工况 NMSE 范围 0.030–0.246，是唯一高 Ro 不退化的模型；但 exp(4.02·eta2²/s2o2)
  增益偏大，建议使用前核查饱和比例（沿用验收第 6 规则）

### 4.4 LGF 其余公式（可解释性均好）

- lgf_go/v (0.238): `C4·ret + C3·roloc − C2·ret/(roloc + C1)`
- lgf_mg/v (0.229): `C4·roloc/((roloc+C3)·(C1·roloc + C2 + zeta2 + 1))`
- lgf_go/e (0.374): `C4·ret − C3·zeta2/(s2o2+C2) − C1·zeta2`

## 6. 分析与讨论

1. **方法维度**：单输出任务上 PySR 与 LGF 各有胜场——PySR 快 20 倍且 e/m 变体强；
   LGF（heuristic）公式更简洁、g 变体强。lgf_go 与 lgf_mg 之间无系统性差异
   （v: 0.238 vs 0.229，g: 0.440 vs 0.110，e: 0.374 vs 0.441），与 v3 消融
   "M_GUIDE 无系统收益"结论一致；lgf_mg/g 的大幅领先是单 seed 结果，不能归因于
   M_GUIDE 机制本身（heuristic 后端的 M_GUIDE 只是固定指令变异）。
2. **变体维度**：单公式 b23 任务中 v/g/e 差异在方法间不一致（PySR 最优 e、LGF 最优 g），
   属 seed 级噪声，**不构成对 10-09 "v 胜出"或 10-10 TBFCM "e 胜出"结论的修正**——
   那些是多分量/多公式骨架下的结论，任务不同。
3. **与 TBFCM 的关系**：TBFCM（b_ij=Σg_m(I)·T_m,ij 多公式骨架）解决的是"6 分量同时
   拟合且不塌缩"；本实验解决的是"只要 b23 时的极致精度"。若下游只需 <vw>，单输出
   重训练是更直接、更轻量的路线。
4. **对涡量输运方程 (2) 的可用性**：lgf_mg/g 公式只含 roloc 与 s2o2 两个局部量，
   无壁距、无非局部项，可直接作为代数闭合嵌入。

## 7. 局限

- ⚠️ LGF 全部为 heuristic 离线后端（API key 未设置）；lgf_go/lgf_mg 差别仅在初始种群
  与固定指令变异，**不代表真实 LLM 指导效果**。设 `LGF_LLM_API_KEY` 后建议用 minimax
  重跑 lgf_go 列（P2 决策：真实 LLM 必配 ginit_only）。
- 单 seed；lgf_mg/g 与 pysr/e 的差距（0.110 vs 0.146）未经 cross-seed 验证。
- lgf_go/m、lgf_mg/m 两组未完成（43 维 LGF 单代过慢，已终止进程）；m 变体结论以
  PySR/m 为准。
- 所有指标为训练工况内评估（5 工况联合训练、逐工况报告），无 held-out 工况。

## 8. 建议下一步

1. 用 minimax 真 LLM 重跑 lgf_go × {v,g,e}（~30 min）验证 LLM 通道增益
2. lgf_mg/g 公式 cross-seed ×3 验证 + Ro150 残差来源分析
3. 若采用 pysr/e：核查 exp 增益饱和比例（>50% 拒收）
4. LGF 43 维慢问题：给 fit_joint 的单 start 加 hard deadline（`maxiter` 之外按耗时中断）
